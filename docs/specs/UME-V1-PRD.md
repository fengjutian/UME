# UME V1.0 产品需求文档

**产品名称：** UME（Universal Memory Engine）  
**文档版本：** V1.1  
**文档日期：** 2026-10-10  
**目标读者：** 产品、研发、测试、MiniMax 开发代理  
**代码基线：** `fc9688e7232d7a16d724d2d147bdf9fd587bf9c2`  
**项目仓库：** https://github.com/fengjutian/UME

## 1. 文档目的

本文档基于原始 V1.0 规格书和当前本地代码审查结果重新编写。它定义 UME V1.0 的产品边界、优先级、功能需求和验收标准。

本文档只描述产品应达到的结果。具体模块、数据表、接口和实施顺序见《UME V1.0 技术实现文档》。

## 2. 当前基线

### 2.1 已具备能力

当前仓库已经包含：

- Python 记忆 SDK，入口包为 `ume`，提供记忆创建、搜索、更新、删除和历史查询。
- TypeScript SDK，包名为 `ume`。
- FastAPI 自托管服务，提供 `/memories`、`/search`、`/configure` 等基础接口。
- PostgreSQL + pgvector 的 Docker Compose 开发环境。
- 单管理员注册、登录、JWT 刷新、用户 API Key 创建和撤销。
- 请求日志、请求 ID、限流、配置脱敏和基础实体查询。
- Next.js Dashboard，现有页面包括 Memories、Entities、Requests、API Keys、Configuration 和 Settings。
- Python CLI 和 Node CLI，支持记忆 CRUD、搜索和配置。
- 面向 Claude Code、Codex、Cursor、OpenClaw 等客户端的插件或集成。
- 一个只暴露 `search_memories` 的轻量 MCP 实现，以及若干非 MCP 原生工具集成。

### 2.2 尚未具备能力

以下为 V1.0 的主要缺口：

- 工作区、成员、项目和项目授权模型。
- 原始对话与消息归档。
- 对话导入任务、预览、幂等和失败重试。
- 记忆与消息之间的可追溯来源关系。
- UME 业务层的记忆状态、类型、版本、归档、软删除和恢复。
- 重复与冲突候选管理。
- UME 关系图谱和时间线。
- 面向任务的上下文组装与 token 预算。
- 连接器注册、作用域授权、禁用和撤销。
- 与本地 UME API 对齐的统一 CLI。
- 完整 MCP 工具集。
- 工作区导出、备份与恢复。
- Dashboard 对上述业务能力的页面支持。
- 前端自动化测试和端到端测试。

### 2.3 当前基线限制

- 当前服务只有单管理员模式，不是完整多用户系统。
- API Key 只关联创建用户，没有工作区、项目或操作权限范围。
- 记忆接口接受调用方提交的 `user_id`、`agent_id` 和 `run_id`，尚不能据此实现可靠的租户隔离。
- CLI 默认调用托管平台风格的 `/v1`、`/v2` 路由，与当前自托管 Server 的 `/memories`、`/search` 不一致。
- Dashboard 中 Categories、Webhooks、Analytics 和 Export 仍属于未落地或受限功能。
- 当前没有 `.github/workflows/`，V1.0 不得把“CI 已配置”作为现状。
- `evaluation` 子模块地址仍需在正式开发前确认有效来源。

## 3. 产品定位

UME 是独立于具体模型和 AI 客户端的统一记忆基础设施。它不替代聊天工具，而是为聊天工具、IDE 助手和 Agent 提供统一的长期记忆、对话归档、来源追踪和权限控制。

UME V1.0 由三个核心能力组成：

1. **Memory Engine：** 复用现有 UME SDK 的记忆提取、存储和检索能力。
2. **Conversation Archive：** 保存原始对话、消息、导入批次和附件引用。
3. **Memory Explorer：** 在 Web Console 中浏览记忆、来源、关系、版本和时间线。

## 4. 产品目标

### 4.1 V1.0 目标

- 用户可以创建工作区和项目，并在项目范围内组织对话与记忆。
- 用户可以通过 API、CLI、MCP 或 JSON 文件保存对话。
- UME 可以从对话中提取记忆，并保留消息来源。
- 用户可以搜索、查看、编辑、归档、恢复和删除记忆。
- 用户可以查看记忆的历史版本、来源、关联关系和时间线。
- 用户可以为连接器配置最小权限，并能立即撤销访问。
- 两个不同客户端可以在同一授权项目中共享记忆。
- 所有关键操作都有可追踪的审计事件。
- 系统可以通过 Docker Compose 在本地完成部署、备份和恢复。

### 4.2 非目标

- 自动抓取所有第三方 AI 产品的完整历史。
- 绕过第三方产品的权限或技术限制。
- 训练基础模型或自研向量数据库。
- 在 V1.0 引入独立图数据库。
- 自动裁决所有冲突事实。
- 宣称服务端语义检索具备端到端加密。
- 在 V1.0 实现多组织计费、复杂企业 SSO 或跨区域容灾。

## 5. 用户角色

| 角色 | 说明 | 核心权限 |
| --- | --- | --- |
| 系统管理员 | 管理部署和系统配置 | 用户、模型、备份、系统状态 |
| 工作区所有者 | 工作区最终负责人 | 成员、项目、连接器、导出、删除 |
| 工作区管理员 | 日常管理工作区 | 项目、成员、连接器、审计 |
| 编辑者 | 维护项目知识 | 对话与记忆读写、关系编辑 |
| 只读成员 | 浏览授权内容 | 搜索、查看、导出允许的数据 |
| AI 连接器 | 独立服务主体 | 仅执行授权范围内的具体操作 |

管理员读取私人对话也必须满足工作区权限和审计要求。

## 6. 典型用户旅程

### 6.1 新用户初始化

1. 用户完成首次管理员注册。
2. 系统自动创建默认工作区。
3. 用户创建第一个项目。
4. 用户创建一个项目级连接器凭证。
5. 用户在 CLI 或 MCP 客户端完成连接测试。

### 6.2 导入并提取记忆

1. 用户上传统一格式的对话 JSON。
2. 系统校验文件并展示预览。
3. 用户选择工作区、项目和保存策略。
4. 系统以幂等方式保存对话和消息。
5. 系统按照策略提取候选记忆。
6. 用户从记忆详情跳回原始消息。

### 6.3 跨工具共享项目背景

1. 客户端携带连接器凭证请求项目上下文。
2. 服务端验证连接器、工作区、项目和操作权限。
3. 系统检索相关记忆并按预算裁剪。
4. 响应返回记忆 ID、正文、更新时间和来源引用。
5. 审计日志记录访问主体和被引用的记忆 ID。

### 6.4 修正过期记忆

1. 用户在记忆详情查看当前内容和来源。
2. 用户编辑内容并填写可选原因。
3. 系统创建新版本，不覆盖历史版本。
4. 用户可以将另一条记忆标记为被替代。
5. 时间线展示此次变更。

## 7. V1.0 功能需求

### 7.1 身份与工作区

#### FR-001 工作区管理（Must）

- 创建、查看、修改和删除工作区。
- 默认工作区由首次管理员初始化流程创建。
- 删除前展示影响统计并要求明确确认。
- 工作区删除采用后台任务，记录执行状态和失败原因。

#### FR-002 成员与角色（Must）

- 支持 `owner`、`admin`、`editor`、`reader`。
- 一个用户可以属于多个工作区。
- 所有业务查询必须以服务端解析出的工作区权限为前提。
- V1.0 可先由管理员添加现有用户，不要求邮件邀请闭环。

#### FR-003 项目管理（Must）

- 创建、查看、修改、归档和删除项目。
- 项目包含名称、描述、标签、状态和最近活动时间。
- 对话最多有一个主项目；记忆可以关联多个项目。
- 无法分类的内容进入工作区“待整理”区域。

### 7.2 对话归档

#### FR-010 对话和消息写入（Must）

- 支持 `system`、`developer`、`user`、`assistant`、`tool` 角色。
- 消息保存正文、时间、外部 ID、内容哈希、元数据和敏感级别。
- 多模态内容保存文本与附件引用，不强制转写媒体。
- 单次写入必须是事务性的；失败时不得留下不可识别的半成品。

#### FR-011 JSON 导入（Must）

- 支持格式校验、预览、项目选择、策略选择和导入确认。
- 导入请求支持幂等键。
- 使用外部消息 ID或内容哈希去重。
- 大文件采用后台任务和分批写入。
- 提供任务状态、错误明细、结果摘要和失败重试。

#### FR-012 对话浏览（Must）

- 列表支持游标分页、来源/项目/时间过滤和关键词搜索。
- 消息按稳定顺序分页加载。
- 可以查看该对话提取出的记忆。
- 可以从消息跳转到关联记忆。

#### FR-013 保存策略（Must）

- `archive_only`：仅归档。
- `archive_and_extract`：归档并提取候选记忆。
- `ephemeral`：默认不持久化，用户明确保存后才写入。

### 7.3 记忆管理

#### FR-020 统一记忆视图（Must）

- 在现有记忆引擎记录外增加 UME 业务元数据。
- 业务类型包括 `profile`、`fact`、`episode`、`procedure`、`project`、`decision`、`entity` 和 `working`。
- 状态包括 `active`、`candidate`、`archived` 和 `deleted`。
- 支持类型、项目、来源、标签、状态和时间过滤。

#### FR-021 来源追踪（Must）

- 一条记忆可以关联多条消息。
- 来源记录区分自动提取和手动关联。
- 来源删除后仅保留不可反推正文的墓碑信息。
- 记忆详情显示来源对话、消息、工具、时间和证据片段。

#### FR-022 版本历史（Must）

- 编辑、归档、恢复和关键元数据变化均创建版本或事件。
- 支持比较任意两个版本。
- 恢复旧版本会创建新版本，不删除中间历史。

#### FR-023 删除与遗忘（Must）

- 区分归档、软删除和永久删除。
- 永久删除需要二次确认或显式 API 参数。
- 永久删除覆盖业务表、记忆引擎、搜索索引和可删除的派生数据。
- 备份中的数据按照保留策略到期清理。

#### FR-024 重复与冲突（Should）

- 精确重复可自动标记。
- 语义重复和冲突只能生成候选关系。
- 合并必须保留所有来源和版本。
- 用户可以选择保留、合并、替代或忽略。

### 7.4 图谱与时间线

#### FR-030 关系管理（Must）

- 支持 `derived_from`、`related_to`、`belongs_to`、`supersedes`、`contradicts` 和 `duplicates`。
- 关系状态包括 `candidate`、`confirmed` 和 `revoked`。
- 自动关系必须保存证据或生成原因。

#### FR-031 图谱浏览（Must）

- 从项目、对话或记忆进入局部图谱。
- 支持展开相邻节点、过滤、搜索定位和详情查看。
- 默认限制节点数量，不允许一次性加载全图。

#### FR-032 时间线（Must）

- 展示记忆创建、更新、恢复、归档、删除、合并和替代。
- 展示对话导入和连接器授权变化。
- 支持按资源类型、项目和时间过滤。

### 7.5 连接器、CLI 与 MCP

#### FR-040 连接器（Must）

- 连接器作为独立服务主体，不复用用户全量权限。
- 状态包括 `active`、`disabled`、`revoked` 和 `error`。
- 权限至少区分记忆读写、对话写入、上下文读取和导出。
- 凭证只在创建时显示一次，服务端只保存哈希。
- 撤销后新请求立即失败，既有数据不自动删除。

#### FR-041 CLI（Must）

- CLI 统一连接 `/api/ume/v1`，不再默认依赖不存在的托管平台接口。
- 支持工作区、项目、对话、记忆、上下文和连接器命令。
- 支持 `text`、`table` 和 `json` 输出。
- 危险操作要求交互确认或 `--yes`。

#### FR-042 MCP（Must）

V1.0 至少提供：

- `workspace_list`
- `project_list`
- `conversation_save`
- `memory_add`
- `memory_search`
- `memory_get`
- `memory_context`
- `memory_sources`

每次工具调用都必须执行连接器权限检查、输入校验和审计记录。

### 7.6 上下文组装

#### FR-050 上下文请求（Must）

- 输入包括工作区、项目、任务描述、关键词、类型过滤和预算。
- 服务端先做权限过滤，再执行检索和排序。
- 输出包含记忆 ID、正文、更新时间、来源引用和裁剪信息。

#### FR-051 预算与排序（Must）

- 支持近似 token 预算。
- 优先级为项目约束、任务相关性、决策、时间新鲜度和可信状态。
- 不得把完整历史对话无差别拼接到结果中。

### 7.7 导出、备份和审计

#### FR-060 工作区导出（Must）

- 导出前验证全部对象权限。
- 导出包含工作区、项目、对话、消息、记忆业务元数据、来源、关系和版本。
- 导出文件包含格式版本和校验信息。

#### FR-061 备份恢复（Must）

- 提供 PostgreSQL 和必要文件存储的备份说明或自动化命令。
- 恢复前校验版本和完整性。
- 至少有一个自动化恢复测试。

#### FR-062 审计（Must）

- 记录主体、动作、资源、结果、请求 ID 和时间。
- 上下文访问记录返回的记忆 ID，不默认记录完整正文。
- 日志不得包含密码、令牌、完整 API Key 或认证头。

## 9. 非功能需求

### 9.1 安全

- 生产环境禁止 `AUTH_DISABLED=true`。
- 所有业务表必须带工作区边界或可可靠推导工作区。
- 所有查询在数据访问层执行权限约束，不能只在路由层过滤结果。
- API Key 和连接器密钥采用带盐哈希或专用密码哈希算法保存。
- 所有越权访问返回 404 或统一权限错误，避免资源枚举。

### 9.2 性能

- 不含 LLM 的普通列表查询 P95 小于 500 ms。
- 记忆详情 P95 小于 300 ms。
- 图谱局部查询 P95 小于 1 秒。
- 导入 10,000 条消息时可分批执行、可查看进度且不会阻塞 API 进程。
- 性能指标必须在验收环境实际测量，不得使用推测值作为报告结果。

### 9.3 可靠性

- 写入失败不得静默吞错。
- 可重试写入必须具备幂等性。
- 数据库迁移失败时服务不得继续执行破坏性写操作。
- LLM 提取失败不得丢失已经成功归档的原始消息。

### 9.4 可维护性

- UME 业务模块放在独立目录，避免继续扩大 `server/main.py`。
- 数据库变更全部使用 Alembic。
- 公共 API 变更同步更新 OpenAPI、CLI、MCP 和文档。
- 禁止在没有设计评审的情况下引入微服务或新数据库。

## 11. V1.0 验收标准

### 11.1 核心链路

- [ ] 创建工作区和项目。
- [ ] 导入一份包含至少 100 条消息的对话文件。
- [ ] 重复导入不会产生重复消息。
- [ ] 从对话提取记忆并可追溯到来源消息。
- [ ] 编辑记忆后可比较和恢复历史版本。
- [ ] 归档或删除记忆后，搜索结果符合策略。
- [ ] 图谱可以局部展开来源与关联记忆。
- [ ] 上下文接口在预算内返回带引用的结果。
- [ ] CLI 和 MCP 均能访问本地部署。
- [ ] 撤销连接器后请求立即失败。
- [ ] 工作区导出和备份恢复通过验证。

### 11.2 安全

- [ ] 跨工作区读取、搜索、图谱、来源和导出测试全部失败关闭。
- [ ] 伪造资源 ID 不能越权。
- [ ] 日志中没有明文凭证。
- [ ] 被撤销或禁用的连接器不能继续访问。
- [ ] 生产配置无法在无认证模式启动。

### 11.3 质量

- [ ] Python lint、单元测试和集成测试通过。
- [ ] TypeScript 类型检查、格式检查和测试通过。
- [ ] Dashboard 关键旅程的 Playwright 测试通过。
- [ ] 数据库迁移可从空库执行，也可从当前基线升级。
- [ ] 文档中的命令已在目标环境实际执行。

## 12. 产品决策与待确认项

开发前必须确认：

1. UME 是否坚持完全移除上游兼容名称，还是保留仅用于迁移的兼容层。
2. `https://api.ume.ai`、`https://docs.ume.ai` 等域名是否真实可用；不可用时本地部署必须默认使用用户配置地址。
3. `evaluation` 子模块的新仓库地址。
4. V1.0 用户创建方式：仅管理员创建，还是提供邀请流程。
5. 附件存储使用本地文件系统还是 S3 兼容接口。
6. 永久删除在备份中的最长清理周期。
7. 是否允许在获得维护者批准后创建 `.github/workflows/`。
